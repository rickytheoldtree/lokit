# 本地化工具

基于 .NET 8 / WPF UI 的本地化编辑和翻译工具，统一使用 `.locproj` 项目工作副本。

## 日常流程

1. 点击「新建项目」，选择游戏使用的正式语言目录（可以是空目录），确认语言文件命名规则、文件格式和源语言，再选择 `.locproj` 的保存位置。创建时只读取规则中匹配的语言文件，不修改正式目录。
2. 在「新增」页填写或粘贴以 Tab 分隔的 Key / 文本，点击「加入项目」。内容立即进入项目源语言，无需拷贝文件。
3. 在「翻译」页选择目标语言和翻译方式。结果保存到项目工作副本，可直接到「编辑」页检查、修改并保存。
4. 点击「预览发布」核对各语言的新增、修改、删除，再点击「备份并发布」写回正式目录。
5. 下次启动会重新打开上次项目，也可以通过「打开项目」切换。

任务执行窗口会显示当前翻译步骤和运行时长，可随时安全取消。设置页「应用外观」支持跟随 Windows、浅色和深色模式；主窗口与任务窗口共用主题和标题栏标识。

不再提供旧目录模式、单独导入语言目录或迁移入口。程序不会清理已有的旧目录或文件。

## 保存与发布

- 「保存 / 加入项目」只更新 `.locproj`，不会直接修改游戏文件。项目里已保存但未发布的更改，关闭程序后仍保留；尚未保存的表格编辑会询问如何处理。
- 源语言、语言映射和转换器随项目保存。项目打开期间不能在设置页切换这些配置；新建项目时可以重新选择。
- 自动翻译只处理新增、缺少译文、译文为空或手动标记为待重译的条目，其他已有译文始终保留。
- 产品发现旧词条有问题时，可在编辑页选中 Key 并「标记重译」，选择一种或全部目标语言。新增/缺失 Key 与手动标记的旧 Key 可以在同一次翻译中处理；旧译文会一直保留到对应语言的新结果通过完整校验并成功应用。失败或取消时标记不丢失，也可以用同一入口取消标记。
- 翻译结果会校验 Key 集合、空译文及常见占位符 / 标签（如 `{0}`、`%s`、`<b>`）。源文或译文在请求期间发生变化时，不应用过期结果。仍建议发布前人工检查译文。
- 编辑页「删除选中 Key」会从项目的所有语言中删除该 Key，发布时才影响正式文件。「撤销更改」只恢复当前表格到最近一次保存 / 加载状态，不撤销已经保存的项目操作。
- 发布只写入内容发生变化的语言文件，不创建从未翻译过的空语言文件，也不处理映射规则之外的文件。
- 发布前会核对正式文件是否被外部修改；发现变化就阻止覆盖。本版不自动合并外部变化，需要先核对处理。
- 每次发布先把原文件按原始字节备份到 `<项目文件>.backups`。写入发生异常时尝试回滚；若外部并发修改使回滚无法安全完成，会保留备份并报告具体文件。断电等进程外中断不保证自动回滚。
- 「项目操作 → 恢复上次发布」将正式文件恢复到上次发布前，保留当前工作副本为未发布状态。正式文件在发布后被外部修改时，会阻止恢复。更早的备份保留在备份目录，界面只支持恢复最近一次发布。

`.locproj` 包含各语言内容、基线和正式目录的绝对路径，不包含 API Key。它可以放在游戏目录之外；移动游戏目录后不会自动重定位。保管项目时请同时保留旁边的 `.backups` 目录。`.locproj.lock` 是多实例写入锁文件，可留在原处。

## 环境与翻译方式

- Windows 和 [.NET 8 桌面运行时](https://dotnet.microsoft.com/download/dotnet/8.0)。
- Google / DeepSeek 网页翻译需要本机安装 Edge、Chrome 或 Firefox；API 翻译不需要浏览器。
- API 模式在设置页填写接口地址、Key、模型及提示词。设置保存于本机 `data/config.json`，请勿把该文件作为项目资料分享。

### 浏览器驱动

网页翻译通过 Selenium 工作。程序使用 Selenium Manager 下载与本机浏览器匹配的驱动，并缓存到 `data/web-drivers`。

- 设置页「浏览器」默认为「自动」，优先选择本机 Edge，也可以手动指定。
- 网络受限时可填写「驱动代理」，例如 `http://127.0.0.1:7890`。
- 也可以把对应的 `msedgedriver.exe` / `chromedriver.exe` / `geckodriver.exe` 放入 `data/web-drivers`，下载失败时会回退使用。

### 语言规则与转换器

`data/iso` 中每个文本文件是一组语言规则，每行格式为 `文件名,ISO代码`，例如 `English,en` 对应正式目录中的 `English.json`。转换器实现 `IDictConverter` 接口，扩展 DLL 放在 `data/converters`；接口由解决方案单独生成 `IDictConverter.dll`，发布包中会一起提供。

## 构建与测试

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

该入口会依次检查代码格式、以“警告视为错误”构建整个解决方案，并运行数据与 WPF 界面回归；只需在无桌面的环境验证数据逻辑时可追加 `-SkipUi`。

发布命令：

```powershell
dotnet publish LocalizationTranslationWPF.csproj -c Release -r win-x64 --self-contained false -o release/project-workflow-win-x64
```

回归范围与隔离规则见 [测试说明](Tests/EditingRegression/README.md)。
